How connecting works

This environment mints a state token
Bound to macbook-pro and to your T3 session. Expires in 10 minutes.
Slack asks you to pick a workspace and approve scopes
Opens in your browser. On a remote client the consent page opens where you are; the callback still lands on the host.
Slack redirects to /oauth/callback/slack on the T3 server
The server exchanges the code for a bot token and stores it in the environment's secrets. The browser never sees the token.
This page re-checks the connection
Status flips to Connected and channel access defaults to None until you choose otherwise.
Devin routes this through app.devin.ai (REMOTE). In T3 the redirect URI must be reachable by Slack, which means a public origin: T3 Connect tunnel or a hosted relay. Open question in README §3.

Disconnect Slack?

The bot token for Acme Inc is deleted from this environment and the app is uninstalled from the workspace.

  • 2 automations use a Slack notification and will show "needs Connections".
  • Open threads started from Slack stay, but replies stop posting back.
  • Channel selections and routing are forgotten; reconnecting starts from None.
